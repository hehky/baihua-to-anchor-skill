# 白话转锚点 v3.1.0

本文件是唯一规则。你（模型）读完后亲自执行：判场景 → 切子句 → 归锚点 → 清洗 → 补默认与代推 → 自查 → 输出 → 执行。词库 `lexicon.json` 与本文件同目录，只提供词表数据；词表的含义与用法全部以本文件为准。转写的本质是**删掉没有信息量的词，其余一字不改**，不替用户做决定。

规则冲突时的总优先级（高的压低的）：
**§0 总原则 > §1 术语定义 > §3 场景决策链的顺序 > §6 子句归属顺序 > §8 允许的改写 > §11 示例**。示例与规则不一致时以规则为准，并视为 bug 修示例。

---

## §0 总原则（先读这一段，全文按它理解）

1. **执行者是模型，词库是"种子示例 + 判定提示"。** 场景判定、症状判定（系统是不是坏了）、风险判定、`h:` 判定一律**以语义为准**。词库里的词条、正则和兜底规则是常见说法的样本：字面命中用来提示方向，并在语义含糊、两种判法都说得通时打破平局；不要求逐字命中，字面命中也不能压过明确的语义。本文件里凡说"命中""匹配""含某词表"，除第 2 条的硬规则外，都按这个意思理解。
2. **只有这几条是硬规则，逐字执行、不做语义变通**：① 行首锚点（§3 第 1 条）；② 否定不丢、不反转（§8 改写③）；③ 代码、路径、URL、命令、报错原文、数字等技术片段逐字保留（§7）；④ 输出格式与顺序（§7 行序、§10.1）；⑤ 学习防污染（§13.6，由 `learn.py` 强制）。另外，口水词只删词库里有的（§8 改写①），这是"不改用户原话"的底线，同样按字面执行。
3. **场景看动作子句的意图**：判场景只看用户要我做的那件事（动作子句）。现状、症状、红线子句里出现的场景词不参与（"每次部署完要手动重启 nginx，能不能自动化"要做的是自动化 → `/脚本`，不是 `/部署`）。只有现状、没有动作时，按整句要达成的目的判。
4. **规则没写到的情况，按最贴近的规则类推**，结论要能用一句话说出理由。拿不准时选更保守、更少替用户做决定的写法（不删、不推、多问一句）；但能从项目本身推断的默认（用哪种语言、沿用现有框架）不为它打断用户。

## §1 术语表（一个概念只用一个名字）

| 术语 | 定义 |
|---|---|
| 合法锚点（输入） | `z:` `i:` `x:` `o:` `h:` `y:` `j:` `q:` `s:` `r:`，小写字母 + 半角或全角冒号。`ERROR:` `R:` 不是 |
| 输出锚点 | 转写产物只用 8 个：`z:` `i:` `x:` `o:` `h:` `y:` `q:` `j:`（`s:` `r:` 是用户专用，不输出） |
| 行首锚点 | 某一行去掉行首空白后以合法锚点开头。行内出现的 `x:` 不算 |
| 场景标签 | `/排障` `/部署` `/配置` `/重构` `/脚本` `/开发` 六个之一，来自词库 `scenes.*.label` |
| 子句 | 用全角 `，。；！？`、换行切开的片段；半角 `, ; ! ?` 只在两侧都是汉字时才算分隔。技术片段内部不切 |
| 技术片段 | 必须一字不动的片段：代码块、行内代码、路径、URL、命令、报错原文、数字，以及原话里任何一段连续的英文/数字/符号（ASCII 片段） |
| 命令 | 作为**可执行命令原文**出现的一段：工具名后跟真实的子命令、参数或选项（`nginx -s reload`、npm run dev、npm install、vite build、docker compose up、systemctl status、git rebase），或带反引号，或有管道、重定向、`&&` 等明显的 shell 语法。工具名单独出现、或后面跟的只是白话动作（「nginx reload」的 reload 只是"重载"的英文说法，真实命令是 `nginx -s reload`；「跑 eslint」「pytest 报…」「npm 报…」）都不是命令，是单独点名（§7 `h:`） |
| 动作子句 | 归入 `x:` 的子句（含只剩技术对象、要代推动作的子句）。`y:` `z:` `q:` `j:` `o:` `i:` 子句都不是 |
| 症状词 | 表示"用户的系统现在坏了"的说法。词库 `symptoms.words`（英文不分大小写）与 `symptoms.patterns`（正则）是种子与快速通道，判据是语义（§0、§4.1） |
| 排除词 | 词库 `scene_exclusions.<场景>`：含触发词/症状词字样但不表示该场景的词（周报、发布订阅…） |
| 功能名 | 症状词出现在"要做的功能"里，不是症状（异常检测功能、失败重试），判据见 §4.3 |
| 坏味道 | 词库 `bad_smells`（太长、太乱、太慢…）：代码不好但没坏，进 `z:`，不触发排障 |
| 触发词 | 词库 `scenes.<场景>.triggers`：各场景的常见说法（种子示例），只在动作子句里看。字面命中是强提示，场景以动作意图为准（§3 第 6 条）；词条里的 `…` 表示中间可插 0–4 个非标点字符（`改…配置` 命中"改一下配置"） |
| 兜底规则 | 词库 `scene_fallback.rules`：意图不明、也没有触发词时的提示规则，只看动作子句；正则是样本，"对象是代码"这类条件按语义认定 |
| 诊断动词 | 叫我先看看情况的动作（看看 / 查一下 / 瞅瞅…）。词库 `feature_name_rule.diagnose_verbs` 是种子，学习层 `diagnose_verbs` 可扩充；用户说了就是明说的动作 |
| 口水词 | 词库 `colloquial` 七类里的词。带上下文条件的词以 `deletion_context` 的正则为准，只在命中时删 |
| 用户原话 | 用户说出的内容，只经过 §8 允许的改写 |
| 默认项 | 用户没说、由场景补出的 `i:` / `y:`，带默认标注（`default_tags`） |
| 代推 | 用户没说、由你推出的 `x:` 行，带代推标注（`infer_tags`），只有 `x:` 会代推 |
| 会话锁 | 某任务首次输出转写后进入的状态：同一任务的后续白话消息直接转写，不再判"是否工程任务" |
| 结束消息 | 会话锁内，消息的每个子句都是结束短语、致谢、问候或语气词（§5） |
| 随附话 | 输出末尾给用户的一句话：确认代推、方向提问、风险征询或执行宣告（§10） |
| 学习结算行 | `[学习] 新增词条 N / 纠错 M`，可带 `候选：…`（§13） |
| 种子层 / 学习层 | 词库里人工维护的词表 / `learned` 区自动学习的词条；学习层 `count>=active_min_count`（=2）才**生效**，否则只是**候选** |

## §2 总流程（7 步）

1. **读词库**：先按 `lang/en.md` §1 选语言包（白话是中文用 `lexicon.json`，是英文用 `lang/lexicon.en.json`，规则不变、只换词表与字面记号，不翻译），加载对应词库，`schema_version` 必须为 3，否则停手并告诉用户词库版本不符。生效的学习层词条并入对应种子词表一起用。
2. **判场景**：按 §3 决策链，第一条命中即停。结果是"不触发"或一个场景标签。
3. **切子句、归锚点**：按 §6 的顺序给每个子句定唯一归属。
4. **清洗**：只做 §8 允许的五种改写。
5. **补默认与代推**：按 §9。
6. **自查**：按 §12 逐项过，不过就改。
7. **输出、执行、学习**：按 §10 输出并执行；按 §13 做学习判定并写结算行。

## §3 场景决策链（有序，第一条命中即停）

1. **行首锚点** → `不触发：行首锚点，按 v5.2 原生规则解析`。会话锁内同时解锁。
2. **退出短语**：消息含词库 `opt_out` 里的短语（直接做 / 别转写 / 不用套规范…）→ `不触发：用户要求不转写`。
3. **会话锁**（只在锁定期内走这一条）：
   - 3a 结束消息（§5）→ `不触发：会话结束，解锁`。
   - 3b 只有致谢、寒暄、不带新内容的反馈（"好了，结果没问题"），或与当前任务无关的提问（知识问答、怎么做的咨询）→ `不触发：…`，锁保持。
   - 3c 另起的新任务（对象与上一轮无关）→ 旧锁解除，从第 4 条重新判。上下文里没有上一轮的对象信息（只知道上一轮场景）、判不了"无关"时，带「顺便 / 再 / 还有」（`session.append_markers`）的消息视为同一任务的追加 → 3d；没有这些词也判不了时，同样按 3d 处理（更少替用户做决定）。
   - 3d 其余一律转写：场景继承上一轮；只有本轮由第 5 条判出 `/排障`，或由第 6 条判出优先级更高的场景时才换。第 7 条兜底规则在锁内不参与换场景。
4. **不是工程任务** → `不触发：…`。包括：闲聊、问候、致谢；非工程请求（写诗、天气）；**知识问答 / 选型咨询**——问概念、原理、区别、怎么选（词库 `knowledge_question` 是常见说法），且句中既没有用户自己系统的现状，也没有要我对用户的代码/文件/环境动手的动作。句里有用户自己的对象加动作或症状（"帮我看看这个正则为什么匹配不上 123-45678"）就是工程任务，继续往下判；"怎么办 / 不知道怎么继续"带着用户自己仓库或系统的现状（"git rebase 到一半冲突了，现在不知道怎么继续"）也是工程任务。翻译或编写项目文档（README、接口文档）是对用户仓库文件动手，属于工程任务。
5. **系统已坏** → `/排障`。整句的现实解释是"用户的系统现在坏了"就判排障，细则见 §4。git 正常工作流卡在半途（rebase / merge / cherry-pick 冲突、push 被拒、pull 冲突）也在这里判 `/排障`，代推写法见 §9。这一条排在意图和兜底规则之前。
6. **意图场景**（只看动作子句，§0 第 3 条）→ 判动作子句要做的事属于**排障以外**哪个场景（§3.1 意图表），意图明确就取它，即使字面命中了别的场景的触发词（".env 里加个 SENTRY_DSN=…"命中开发的「加个」，意图是改配置 → `/配置`）。意图说得通两种以上时，在动作子句里找触发词（先遮掉该场景的排除词），按词库 `scene_priority`（排障 > 部署 > 配置 > 重构 > 脚本 > 开发）取最高。
7. **兜底规则** → 意图不明、动作子句里也没有触发词时，按 `scene_fallback.rules` 顺序取第一条成立的规则（正则是样本，按语义认定）：
   - 规则 1–3 → `/配置`：动作子句里有 配置 / 参数 / 开关 / 环境变量；或配置文件（按语义认定：`.yaml` `.yml` `.json` `.toml` `.ini` `.conf` `.cfg` `.properties` `.env` 只是样本，`settings.py` `config.py` `*.config.js` 这类配置模块也算）加 改成 / 调成 / 设成 / 设为 / 改为 / 加 / 新增 / 删掉 / 去掉；或 改成 / 调成 / 设成 / 设为 / 改为 + 数字。
   - 规则 4 → `/重构`：拆了 / 拆开 / 拆成 / 拆掉 / 合并成 / 合并到 / 抽出 / 抽成，**且**同一动作子句的对象是代码，**且**不是版本控制动作（`exclude`：分支、branch、main、master、release、tag、PR、MR、commit、提交、git、仓库）。"对象是代码"（`requires`）按语义认定：带扩展名的文件名、类名（UserController 这类驼峰名）、函数、方法、模块、文件、组件、中间件、代码、接口都算，不要求出现"类 / 函数"字样。只有这条规则 `learnable: true`。
8. **默认** → `/开发`。

场景是转写内部的判定，不列代推项，也不问用户。

### 3.1 意图表（第 6 条的判据；例子和触发词一样是样本）

| 场景 | 动作子句的意图 | 例 |
|---|---|---|
| `/部署` | 把代码或服务装到、发布到、升级到某个环境 | 上线 v3.2 到生产、部署到测试机、装环境 |
| `/配置` | 改配置项、参数、开关、环境变量；在配置文件或 `.env` 里加、改、删键值；动作不明但对象只是配置文件。配置文件按语义认定：`settings.py`、`config.py`、`*.config.js` 这类配置模块也算，扩展名只是样本 | 把 maxmemory 设成 2gb、在 .env 里加个 SENTRY_DSN=…、在 settings.py 里加上 CORS_ALLOWED_ORIGINS、修改 nginx.conf |
| `/重构` | 外部行为不变的改进：拆分、合并、抽取、整理、解耦；性能优化（含加索引）与改写实现 | 压到 3MB 以下、把 for 循环改成 map、慢查询优化、给 orders 表加索引、把函数改成异步的 |
| `/脚本` | 写或改一个要运行的脚本、批处理、定时任务；把手工流程自动化；**一次性运维操作**（删文件、清目录、重启服务、杀进程） | 写个 shell 脚本打包日志、部署后重启能不能自动化、删除 /data/tmp 下所有文件、重启测试机上的 nginx |
| `/开发` | 新功能、新代码；写、翻译、生成项目文档；数据或版本迁移；版本控制操作（删分支、合并分支）；其余工程任务 | 加个字段、把 README 翻译成英文、生成接口文档、迁移 MySQL 数据 |

`/排障` 不在表里，只由第 5 条判出。

**一次性运维操作归 `/脚本`**：它和脚本一样是"在用户环境里跑一串命令完成一次处理"，而 `/部署` 是装、发、升级，`/配置` 是改配置项，`/开发` 是写代码。界线：改配置项仍归 `/配置`；装、发布、升级仍归 `/部署`；删分支、删 tag 这类版本控制操作仍归 `/开发`。运维操作的默认项：`i:操作完成且未波及范围外（默认）`（词库 `scenes.脚本.default_i_ops`，取代"脚本可运行并完成目标处理"）；默认 `y:` 不写（和 `/脚本` 一致：范围已写在默认 `i:` 里，删、清这类风险靠 §10.3 的风险征询兜住），用户给了红线照写。

## §4 "系统已坏"判定（决策链第 5 条的细则）

### 4.1 判据
系统已坏 = 句中有**有效症状**，或虽然没有任何症状词、但整句的现实解释就是用户的东西现在坏了（"首页图片全都裂开了""分页不对，第二页和第一页数据重复了"）。词表只是快速通道，整句解释才是判据（§0）。

整句解释的几条裁决：
- **算坏了**：git 工作流卡在半途（rebase / merge 冲突、push 被拒）；功能结果错误（分页数据重复、时区差 8 小时）。
- **不算坏了**：文档与实现、两处数据对不上而不知道哪边错（"接口文档里的示例和实际返回不一致"）→ 按动作判场景，随附话问以哪边为准；用户明说某一边错了（"接口返回的字段和文档不一致，接口有 bug"）才判排障。慢和耗时（"太慢了""查询要 20 秒"）是坏味道，不是坏了。

### 4.2 有效症状的认定（按顺序）
1. **最长匹配**：症状词与排除词重叠时取更长的那个。`报错率飙升了` 里症状 `报错率飙升` 比排除词 `报错率` 长 → 是症状；`接入天气预报 API` 里排除词 `预报` 遮住了 `报 A` → 不是症状。
2. **排除词只遮它自己那几个字**：遮掉后句里仍有别的症状词，照判排障（"登录接口的异常处理有问题"：遮掉不在表里的部分无影响，`有问题` 仍是症状）。
3. **不是功能名**（§4.3）。
4. **不是坏味道**：`太慢了` `太乱了` 是坏味道，不是症状。

### 4.3 功能名判据（三条都满足才算功能名，不触发排障）
- 同一子句里症状词**前面**有建造动词（= 词库 `scenes.开发.triggers`：写一个 / 写个 / 实现 / 新增 / 做一个 / 做个 / 加个 / 加一个 / 开发 / 支持 / 设计 / 搭一个 / 搭个）；
- 该子句里没有修复动词（`feature_name_rule.repair_verbs`：修复 / 修好 / 修掉 / 修一下 / 修 / 解决 / 排查 / 定位 / 处理掉）；
- 该子句里没有状态标记：状态副词（`state_markers`：一直 / 总是 / 老是 / 突然 / 又 / 还是 / 现在 / 每次 / 偶尔 / 经常）；「了」**紧跟在症状词后**（`state_suffix`，"崩溃了"算，"新增了失败重试"不算）；「动作 + 后」（`after_verb_pattern`，上线后 / 部署后 / 升级后 / 切路由后 / 新增功能后；后端、后台、后续不算）。

另一种功能名：**条件从句里的症状词**——症状词在条件部分（后接 `conditional_markers` 里的 就 / 时 / 的时候 / 则，或前有 如果 / 一旦 / 当），而结果部分是要做的动作（"失败了就重试三次""报错的时候写文件"）。症状是结果部分时仍是症状（"上传超过 2MB 就失败了""一跑就报 port 3000 already in use"）。

### 4.4 带形态才算症状的词
`不行` `不对` `不一致` `失效` `超时` `满` 不是裸症状词，只有这些形态才算（已写进 `symptoms.patterns`）：前面有状态副词（还 / 也 / 都 / 一直 / 又 / 总是 / 突然 / 现在 / 每次 / 老是 / 还是 / 偶尔 / 经常 / 时不时，可带「是」），或后接「了」，或「失效」在子句末尾。"这个方案不行""分页不对""把缓存失效时间改成 10 分钟""请求超时要重试"都不是症状（是否坏了交给 §4.1 的整句解释）；"还是不行""缓存失效了""接口一直超时""单测偶尔超时""连接池老是满"是。`不对` `不一致` 和 `不行` 一样泛，在 `generic_words` 里，不学成触发词。

### 4.5 当前种子
- `symptoms.words`：报错、报异常、抛错、抛异常、抛出异常、崩溃、闪退、白屏、黑屏、卡住、卡在、卡死、挂了、宕机、起不来、跑不起来、跑不了、跑不通、启动不了、打不开、访问不了、连不上、连接不上、连接超时、登不上、点不动、没反应、匹配不上、不工作、不生效、没生效、出问题、有问题、失败、被拒、拒绝访问、泄漏、泄露、不可用、用不了、乱码、死循环、bug、failed、exception、traceback、timed out、rejected、refused、denied、panic、segmentation fault、out of memory。
- `symptoms.patterns`：`报 + 英文/数字`（报 500、报 TypeError、报 port…）；`报/抛 + 至多 4 字 + 错误/异常/越界/溢出/空指针`；`XxxError` / `XxxException`；`ERROR:` / `Error:` / `error:`；`一直/又/偶尔/总是/老是/经常/时不时/出现/状态码/HTTP/全是/都是/全都是/全部是 +（返回/报）+ 4xx/5xx`（"图片路径全是 404"）；`返回 + 4xx/5xx`，后面不接「的」（"接口返回 500"算，"返回 401 的逻辑"这类要做的功能不算）；`4xx/5xx + 错误/Bad Gateway/Forbidden…`；§4.4 的形态；`报错率/错误率/失败率/超时率 + 飙升/上升/升高/激增/变高/突增/暴涨`。

- 裸「错误」「异常」「报」不是症状词；它们只在场景已判排障后照原话进 `z:`。

## §5 会话锁

- **进入**：某任务首次输出转写结果（含大任务只出了计划骨架、还在等确认）即进入锁定。
- **锁定期**：按 §3 第 3 条处理。短消息（"还不行""再试一下""继续"）照转。
- **结束消息**：消息里**每个子句**都是以下之一才算：`session.end_phrases` 里的短语（好了 / 行了 / 可以了 / 搞定了 / 搞定 / 结束 / 结束吧 / 不用了 / 没事了 / 没问题了 / 完成了 / 就这样 / 算了 / OK了 / ok了），或「至多三个字 + 好了」（`end_verb_pattern`：部署好了 / 改好了），或致谢、问候、语气词。整子句比对，不做子串匹配：「还是不行了」不含结束短语子句；「部署好了，页面还是白屏」「部署好了但页面打不开」有非结束子句 → 不是结束，照常转写（后者判 `/排障`）。带「吗」的问句（"搞定了吗"）不是结束。
- **解锁**：结束消息；任务已确认完成；行首锚点；另起新任务（3c）。
- 「搞定」只在结束消息里表示结束；在任务子句里（"务必今天搞定"）是普通实义词，不替换、不删。

## §6 子句归属（每个子句只有一个归属，按顺序取第一个命中的）

先删掉子句里的口水词（§8），再判：

1. **空子句**（删完口水词什么都不剩）→ 丢弃。
2. **`j:` 子句**：含 `anchor_patterns.j:` 标记（只要代码 / 别解释 / 直接给命令…），说的是**我回复的呈现形式** → `j:`，原样保留（不做否定归一）。
3. **`q:` 子句**：含 `anchor_patterns.q:` 标记（务必 / 一定要 / 今天就要 / 今天要 / 马上 / 尽快…），且除标记外只剩无对象的完成词（搞定 / 完成 / 要 / 用 / 交付）→ `q:`。标记嵌在有具体内容的子句里时，标记留在原子句，子句按后面各条归属（"一定要兼容 IE"→ 红线 `y:`；"这个接口今天必须上线"→ `x:`），不另起 `q:`。
4. **症状子句**：含有效症状（§4）→ `z:`。子句里同时有修复动词或诊断动词（`diagnose_verbs`：看看 / 看下 / 看一下 / 查一下 / 查查 / 查下 / 分析一下 / 瞅瞅 / 瞅一下 / 瞧瞧 / 瞧一下；语义上是诊断动作的同样算，并按 §13.2 列候选）时：整句进 `x:`，`z:` 只截取该动词（取最长匹配，含紧跟的 一下 / 掉 / 好 / 下）**后面**的症状部分。症状子句里的其它动作词是现状（"部署完还是不行"的「部署」），不进 `x:`。
5. **`y:` 子句**：红线与限制——否定词 + 动词或名词（别动 / 不要删 / 千万别覆盖 / 不能超过 / 不要 Redis…）、`必须` `得保证` `得都` `得能` `不超过` `不低于` `至少` `最多` `只能`，或 `q:` 标记 + 具体要求 → `y:`。「得 + 动作」（得换 Memcached / 得改成异步）是动作，不是红线。若这个子句是整条消息里唯一的动作来源（去掉它就没事可做，如"这个接口今天必须上线"），它按动作子句进 `x:`，限制词原样留在 `x:` 里；有别的动作时才进 `y:`（"新增导出按钮，必须支持 10 万行"）。否定词组成名词时不是否定（别人 / 别的 / 区别 / 不可用…，见 `negation.protect`）。
6. **`i:` 子句**：含 `anchor_patterns.i:` 标记（想让它 / 希望能 / 要它能 / 目标是…），说的是**结果状态** → `i:`。
7. **`o:` 子句**：以 `anchor_patterns.o:` 标记开头（给我个 / 给我一个 / 给我一份 / 来一份 / 出一份 / 需要一个…），点名要一个产物 → `o:`，标记词删掉，只留产物名（§8 改写④）。"写个脚本""生成一份文档"是动作，不是 `o:`。
8. **动作子句**：有要我做的动作动词（含单独成句的诊断动词"瞅瞅"），或是祈使尝试语（`imperatives`：再试一下 / 重试 / 再跑一遍 / 继续…），或是"X 时 Y / X 的时候 Y / X 前 Y / X 后 Y / X 就 Y / 如果 X 就 Y / X 要 Y"且 Y 是要我做的动作 → `x:`，条件 X 不拆出来（"今晚 12 点后再发"是动作子句，时间条件留在里面）。按语义排除两种：尝试语不是祈使用法（"现在不知道怎么继续""没法继续"）是现状；"X 要 Y"的「要」是"不得不"、描述用户现在的手工流程（"每次部署完要手动重启 nginx"）是现状。两者都落到第 10 条进 `z:`。还有一种不算动作子句：托付套话或弱化动词删掉后，句里没有用户明说的主动作，剩下的子句只是在规定**怎么解**（"保留双方改动""按上游为准"），它的动词只是解法规格 → 归第 9 条。
9. **需求补充子句**：没有新动作、补充上一个动作或产物的规格（范围、数量、格式、期限要求，以及技术选型，如"三个模块""Markdown 格式""每页 20 条""用 Rust""用和风天气的 API"）→ 并进它补充的那一行（通常是前一个 `x:`，修饰 `o:` 产物时并进 `o:`）。没有用户明说的主动作时（第 8 条末尾的解法规格），按 §9 代推主动作，规格并进代推行：`x:处理<现状>，<规格>`+代推标注。技术选型不是红线，不进 `y:`；其中的技术名另按 §7 抄 `h:`。
10. **现状子句**：没有要我做的动作、描述现状或评价（"太乱了""这个方案不行""安卓正常""要 3 秒""跑一晚上占了 8G"），包括用户自己已经做过的事（"看了一下""计算了一下"）→ `z:`。
11. **只有技术对象**（删完口水词只剩 "nginx 配置"）→ 是动作的宾语：有用户明说的动作就并进那一行 `x:`；没有就写代推 `x:`（§9）。

同一锚点的多个子句按原话顺序合成一行，用「，」连接。`h:` 不是子句归属，是抄录，见 §7。

## §7 锚点细则

**行序**（固定）：`/场景` → `z:` → `i:` → `x:` → `o:` → `h:` → `y:` → `q:` → `j:`。没有内容的锚点不写，不留空锚点。同一锚点只在 `x:` 上可能有两行：用户原话一行在前，代推一行紧跟其后。

| 锚点 | 写什么 | 要点 |
|---|---|---|
| `z:` | 症状、报错原文、现状、坏味道 | 只来自用户原话；报错原文一字不动；用户说"好像/可能/疑似"就原样保留，不加标注 |
| `i:` | 结果状态 | 用户说了就用用户的；没说用场景默认 `i:` 并标「（默认）」 |
| `x:` | 要做的动作 | 用户的动词原样保留（不把"拆了"改成"拆分"）；没有动作才代推 |
| `o:` | 用户点名要的产物 | 只写产物名，标记词删掉 |
| `h:` | 语言、版本、系统、框架、中间件、数据库、平台、工具 | **抄录**：原话里单独点名的技术名抄进 `h:`，原子句照常归属。`anchor_patterns.h:` 是种子不是封闭清单：表外的工程技术名单独点名时也抄（"这段 SQL"→ `h:SQL`），并按 §13.2 列候选。**写法抄原话**（原话 shell 就写 shell，不改成表里的 Shell）；识别时英文不分大小写、按词边界、最长匹配优先（JavaScript 不算 Java）。**命令与单独点名的界线**看它是否作为可执行命令原文出现（§1「命令」）：「nginx reload」「跑 eslint」「pytest 报…」「npm 报…」是白话点名，抄（`h:nginx`、`h:eslint`、`h:pytest`、`h:npm`）。**不抄**：只出现在文件名、命令、报错原文、路径、URL、代码里的（redis.conf 的 redis、vite build 的 vite、npm install 的 npm、docker compose up、systemctl status、`nginx -s reload` 的 nginx、`pytest -x tests/` 的 pytest——这几个都带真实子命令或参数；Cannot find module 'webpack' 的 webpack 在报错原文里）；数据服务商与业务产品（和风天气）；协议名（http、https）；文件 / 文档格式名（Markdown、JSON、YAML、CSV、Excel、png、webp）；泛称（CI、前端、数据库、服务器）。版本跟在名字后，多项用「、」分隔，同名多版本各写一项（`h:MySQL 5.7、MySQL 8.0`） |
| `y:` | 红线与限制 | 一条不丢；否定按 §8 改写③ 归一；用户给了红线就不写默认 `y:` |
| `q:` | 独立的强调子句 | 见 §6 第 3 条 |
| `j:` | 我回复的呈现形式 | 原样保留；产物本身的格式要求是需求补充，不进 `j:` |

**技术片段保护**：技术片段内部不删、不改、不切，换锚点也整段搬。原话里有多行代码块时，代码块整段放进它所属锚点行的后面（锚点行以 ```` ``` ```` 开头的代码块结尾），此时外层输出代码块改用四个反引号 ```` ```` ````。

## §8 清洗：允许的改写只有五种

除下面五种外，一个字不改（不在词表里的"下""一下"不删；"弄坏""搞定""搞不清"是实义，不动）。按规则把子句分到不同锚点、从修复子句里截取症状部分，只是截取，不算改写。

1. **删口水词**：词库 `colloquial` 七类（问候语、客套、托付套话、填充词、弱化动词、委婉句式、语气词）。规则：
   - 只删完整词，不删词的一部分（"请求""整数""整理代码""超级管理员""文件存在吗"一律不动）；
   - 词在 `deletion_context` 里有正则的，只在正则命中时删：「请」只在 请帮/请把/请给… 里删；「在吗」不删"存在吗"；`hi` `hello` 只在消息开头删；「就是 / 其实 / 反正 / 嗯」只在子句开头删；语气词只在子句末尾删；「这个 / 那个」只在后面是标点、句尾或文件名/路径时删（"那个 utils.py"删，"这个函数""这个 bug"保留，是指代）；委婉句式（能不能 / 可不可以 / 可以不可以 / 能否）在后接 把 / 给 / 先 / 再 / 直接 时删，弱化动词删掉后成为残片（后接弱化动词，或落在子句末尾）时也一并删（"每次提交前自动跑 eslint，能不能搞一下"→"每次提交前自动跑 eslint"），后面是实义动词的真问句保留（"这个能不能用""能不能自动化""测一下代理 IP 能不能用"）；
   - 多个口水词重叠取最长匹配（"帮我搞一下"整段按托付套话删）；
   - 托付套话只删托付部分，不吞用户的动作："帮我看看日志"→"看看日志"；
   - 「然后」（`time_words.filler_when_alone`）：前后都是动作、表示步骤先后时保留（"先构建镜像然后再推到 registry""把 csv 转成 json，然后上传到 S3"）；连接的不是两个动作时按填充词删（"…改成 30s，然后注释里的时序说明别删"后面是红线）。其余时序词（`time_words.step_markers` 里的 先 / 再 / 接着 / 之后 / 最后）不是口水词，一律保留。
2. **弱化动词**：`colloquial.弱化动词` 里的形式（搞一下 / 弄一下 / 整一下 / 搞好 / 弄好 / 整好 / 折腾一下 / 处理一下）**删掉**，不替换成别的动词；删完子句只剩对象时按 §6 第 11 条代推动作。唯一的替换是 `weak_verb_replace`：搞掉 / 弄掉 / 整掉 → 去掉。
3. **否定归一**（只在 `y:` 里做）：`negation.normalize` 里的词（千万不要 / 千万别 / 不要 / 不许 / 不准 / 禁止 / 别）**后面紧跟动词或「把」时**归一成「不」。`negation.keep` 里的词（不能 / 不用 / 不必 / 不可 / 不得 / 不超过）原样保留——它们带情态（"不用"是没必要，"不能"是禁止），合并会丢意思。`negation.protect` 里的词（别人 / 别的 / 区别 / 不得不 / 不可用…）不是否定，原样保留。后面是名词（"不要 Redis"）时也原样保留。
4. **删 `o:` 标记词**：`o:` 子句开头的标记（给我一个…）删掉，只留产物名。
5. **删行内锚点符号**：技术片段以外的行内 `x:` 之类（"需求如下，x:把 main.py…"）删掉符号本身；URL、环境引用里的（`http://x:8080`、`s:dev`）属技术片段，一字不动。

保留红线：报错原文、数字、版本号、路径、文件名、库名、时限、否定，一个不丢；白话没说的约束、环境、产物不得捏造。

## §9 默认项与代推

**默认项**（只有 `i:` 和 `y:` 有）：
- `i:`：每个场景都有 `default_i`。用户没说结果状态 → 写 `i:<default_i>（默认）`。
- `y:`：`/排障` `/配置` `/重构` 有 `default_y`。用户没给任何红线 → 写 `y:<default_y>（默认，可删）`；用户给了红线 → 只写用户的。`/配置` `/重构` 的 `y:` 必填，由此保证。
- 默认值逐字取自词库，不改写，不自拟。

| 场景 | 默认 `i:` | 默认 `y:` |
|---|---|---|
| /排障 | 问题消除，功能恢复正常 | 不改动无关的代码和配置 |
| /部署 | 部署完成并可访问 | — |
| /配置 | 配置按描述生效 | 不改动无关的配置项 |
| /重构 | 按描述改进，外部行为不变 | 外部行为不变 |
| /脚本 | 脚本可运行并完成目标处理 | — |
| /开发 | 按描述实现并可运行 | — |

**代推**（只有 `x:` 会代推；`z:` `i:` `o:` `h:` `y:` `q:` `j:` 永不代推）：
- 什么时候代推：没有用户明说的动作（只有症状；只有技术对象；弱化动词删光了）；或 `/排障` 里用户只说了尝试语（再试一下 / 重试 / 继续…），此时尝试语照原话写一行 `x:`，代推另起一行紧跟其后。用户说了诊断动词（看下咋回事）或修复动词，就是明说的动作，不代推。
- 写法（逐字套用，不加诊断、原因或方案）：
  - `/排障`：`x:定位并修复<症状原话片段>（代推：由症状代推）`。锁定期内原话症状没有对象（还不行 / 又挂了）时，片段写「上一轮任务的问题」。
  - `/排障` 且是 git 工作流卡住（§3 第 5 条）：`x:处理<现状原话片段>，恢复到可继续的状态（代推：由症状代推）`。冲突、被拒不是"坏了要修"，不写「定位并修复」。
  - 其它场景：`x:处理<对象原话>，具体动作待确认（代推：由 i: 代推）`。
  - 托付套话 / 弱化动词删掉后只剩解法规格（§6 第 8、9 条）：`x:处理<现状原话片段>，<规格原话>`+该场景的代推标注，规格取代「恢复到可继续的状态」「具体动作待确认」（"merge 的时候冲突了，帮我处理一下，保留双方改动"→`x:处理 merge 的时候冲突了，保留双方改动（代推：由症状代推）`）。
  - **空格**：`<…>` 片段以 ASCII 字符开头时，模板词（定位并修复 / 处理）后加一个半角空格；以汉字开头时不加（`定位并修复 npm run dev…`、`处理 git rebase…`、`定位并修复上线后…`、`处理这段 SQL 查询…`）。
- `<症状原话片段>` 取哪段：取含有效症状的那个子句（"证书过期了，https 打不开"取"https 打不开"）；几个子句都有症状时取第一个；都没有症状词（整句解释判出）时取点名了对象的第一个现状子句（"订单列表接口分页不对，第二页和第一页数据重复了"取"订单列表接口分页不对"）。片段是去掉口水词后的原话，不改写。
- 有代推行时，代码块下方写一行 `代推项：x:`；没有就不写这一行。
- `/排障` 必有 `z:`（判出排障本身就意味着有症状子句）。锁定期继承 `/排障` 而本轮没有症状时，`z:` 沿用上一轮用户原话，行尾标 `（沿用上一轮）`。

## §10 输出格式与执行

### 10.1 触发时的输出（顺序固定，中间不空行）
1. 代码块：第一行场景标签，其后锚点行（§7 行序）；
2. `代推项：x:`（有代推才写）；
3. 学习结算行（必写，§13）；
4. 随附话（一句话）。大任务在随附话后接编号计划骨架：3–5 步，每步一行、一句动作，不写工具、参数、原因等细节（示例 19）。

### 10.2 不触发时的输出
第一行写 `不触发：<理由>`，然后按普通对话或 v5.2 原生规则处理（回答问题、执行锚点指令）。

### 10.3 随附话（只说一件事，按优先级取第一个适用的；唯一例外是风险征询与缺对象同时成立，合成一句）
1. **风险征询**：要执行的步骤里有生产发布或上线、git push / 推送远端 / 强推、合并分支、删除或清空数据、文件、分支、tag，改生产数据或线上库结构（给线上的表加字段、改表、跑线上数据迁移；用户提到"线上数据""生产库"，或对象明显是线上库就算）→ 即使是用户明说的，也先问"要我现在执行吗"，得到同意再做。按语义认定，`risk_actions` 只是样本。用户指定了执行时间（"今晚 12 点后再发"）时问"<用户的时间>要我直接执行吗"，不问"现在"。写一个会删文件的脚本不算，运行它才算。把已经开始的 merge / rebase / cherry-pick 解完冲突并在本地提交，不算合并分支风险；push 到远端、合并到受保护分支（main、master、release 等）才算。
   - **风险 + 缺对象**：风险征询成立、同时缺对象没法动手时，随附话合成一句：先问缺的对象，再说确认后执行（"给 orders 表的哪个字段加索引？确认后今天晚上执行。"）。
2. **方向提问**：缺了对象没法动手，或方向有两种以上实质不同的走法且用户没给可度量目标（"优化下这个页面"：性能还是交互；两边对不上时以哪边为准；rebase 冲突按哪边解决）→ 只问一句。有可度量目标（"优化到 500ms 以内"）且对象明确就不问。没指定语言或框架时按项目现有的来，不为这个提问。
   "缺对象"只在**按上下文和仓库都无法定位**时成立：指代带可搜的特征（名称、类型名、规模、明显的代码结构，如"这个 500 行的 handler""这几个 if else"改策略模式）就先在仓库里搜，定位到再动手，不问（搜出多个候选才问是哪一个）；只有光秃秃的指代（"这个函数""这个接口""这段 for 循环"），上一轮、用户贴的代码、当前打开的文件里也没有，或者全新会话、手边没有仓库上下文时，才问。对象本身要用户来定（"加索引"没说哪个字段、"内存泄漏"不知是哪个进程）时也问。
3. **代推确认**：有代推项 → 问代推动作行不行。
4. **执行宣告**：以上都不适用 → 说明要怎么做。

### 10.4 执行策略
- 小任务（≤2 步、无中间产物）：输出后直接执行；
- 大任务（≥3 步 / 有中间产物要确认 / 一次说不清）：只出计划骨架，等确认后一步一交付；
- 只对代推项、风险步骤和方向问题等用户回答；用户明说的部分直接执行；
- `j:` 约束的是执行阶段交付物的呈现形式，转写块照常输出；
- 用户修正转写（等价 `r:`）→ 改锚点后继续；修正的是代推措辞时按 §13 记纠错；
- 用户后续消息出现行首锚点 → 退出本 skill，按 v5.2 处理。

**示例 20（解法规格并入代推主动作 · 完成 merge 不算风险）**

【输出】

## §13 学习

### 13.1 种子层与学习层
种子层 = 词库里人工维护的全部词表；学习层 = `learned` 区六个桶：`colloquial`（口水词）、`scene_triggers`（触发词，场景为排障时即症状词）、`anchor_patterns`（锚点标记，锚点限 `i:` `o:` `h:` `y:` `q:` `j:`）、`diagnose_verbs`（诊断动词）、`corrections`（纠错）、`rejected`（拉黑）。前四桶的词条 `count>=active_min_count`（=2）才生效，生效后与同类种子词同等使用；`count=1` 只是候选，不参与转写。所以新学的词要在两次不同任务里出现才会改变转写。`corrections` 无门槛、不淘汰；`rejected` 永久拒学。

### 13.2 学习判定（每次转写后做）
四类候选，各有判据；其余一律不列：
- **触发词候选**（去向 `scene_triggers.<场景>`）：只有两种情况——① 场景判为 `/重构`、动作子句里没有 `/重构` 的种子触发词、而兜底规则 4（唯一 `learnable: true` 的规则）成立，列命中片段（拆了 / 合并成 / 抽成…）；② 场景由第 5 条"整句解释"判出且没有命中任何症状词，列句中描述坏掉状态的最短通用说法（2–6 字，不含任务专名，不是 `generic_words` 里的泛词，不与 `bad_smells` 重叠，如"刷不出来""冲突了"），去向 `scene_triggers.排障`；这样的说法找不到（只有"不对""重复了"这类泛词，或只有含数字的说法）就不列。靠触发词、症状词、意图表或不可学的兜底规则判出的场景不列。
- **诊断动词候选**（去向 `diagnose_verbs`，没有子类别）：本次某个动作按语义是诊断动词（叫我先看看情况），但不在 `diagnose_verbs` 里，列这个词，写作 `<词>→diagnose_verbs`。它照样是明说的动作，进 `x:`，不代推。
- **口水词候选**（去向 `colloquial.<类别>`）：本次原话里有、但口水词表没有的问候 / 客套 / 托付 / 填充 / 语气表达，删掉后整句意思不变，至少 2 个字（语气词可单字），且不含任何实义词（`content_nouns`）和信息词。按 §8，本次**不删**它（只有表里的词能删），只列候选。
- **锚点标记候选**（去向 `anchor_patterns.<锚点>`）：本次某子句靠整句理解归入了 `i:` `o:` `y:` `q:` `j:`，但它用的标记不在该锚点的表里（如"十万火急"→ `q:`），列这个标记；或单独点名了 `anchor_patterns.h:` 没有的技术名，列进 `anchor_patterns.h:`。

不学任务内容：文件名、路径、报错原文、数字、版本号永不入库。**数字规则优先于上面各条**：候选里含数字就不列，哪怕按上面的判据本该列（"全是 404"不列）。

### 13.3 学习结算行
格式：`[学习] 新增词条 N / 纠错 M`，有未写入的候选时追加 ` 候选：<词>→<去向>`，多个候选用「、」分隔。N、M 是本次**实际写入**词库的条数（含计数 +1）。能写词库时，对每个候选执行对应的 `learn.py add`，返回码 0 的计入 N、不再列候选；返回码非 0 时 N 不计、照列候选。**只读环境**（不能运行脚本，或词库不可写）：N 和 M 都写 0，候选一个不少地照列，不因为写不进去就省略；用户纠正了代推措辞而记不下时，随附话末尾补一句"这条纠错没能记下"。没有候选就只写前半句。

### 13.4 命令（`<skill目录>` 换成本文件所在目录；下列命令按顺序在一个空学习层上都能跑通）
```bash
python3 <skill目录>/scripts/learn.py add colloquial --text "劳驾" --category 客套 --source "转写时发现"
python3 <skill目录>/scripts/learn.py add scene-trigger --text "炸了" --scene 排障
python3 <skill目录>/scripts/learn.py add anchor-pattern --text "十万火急" --anchor "q:"
python3 <skill目录>/scripts/learn.py add diagnose-verb --text "瞄一眼"
python3 <skill目录>/scripts/learn.py correct --wrong "定位并修复" --right "先复现再修复"
python3 <skill目录>/scripts/learn.py list
python3 <skill目录>/scripts/learn.py list correction
python3 <skill目录>/scripts/learn.py active
python3 <skill目录>/scripts/learn.py remove --kind colloquial --text "劳驾"
python3 <skill目录>/scripts/learn.py remove --kind diagnose-verb --text "瞄一眼"
python3 <skill目录>/scripts/learn.py remove --kind correction --text "定位并修复"
python3 <skill目录>/scripts/learn.py reject --text "炸了" --reason "口语太泛，误伤非故障句"
python3 <skill目录>/scripts/learn.py list rejected
python3 <skill目录>/scripts/learn.py remove --kind rejected --text "炸了"
python3 <skill目录>/scripts/learn.py prune --min-count 2
```
返回码：0 成功；1 拒绝或出错（原因在 stderr）；2 已在种子层、跳过（不算学到）。

### 13.5 纠错
用户纠正的是**你写的文字**（代推行的措辞）时，用 `learn.py correct --wrong A --right B` 记一条，下次代推时用 B 代替 A。纠错只作用于代推行，永远不改用户原话；`--anchor` 只能是 `x:`。`wrong` 至少 2 个字；纠错前后的否定词个数必须相同（不能把"不"纠成"要"）；拉黑区里的词不能用于纠错。

### 13.6 防污染（`learn.py` 强制执行）
- 文本先做 NFKC 归一，比对时不分大小写；拒绝空串、换行和控制字符；长度上限 50（拉黑也一样）；
- 已在同类种子层 → 跳过（返回码 2）；已在别类种子层或别类学习层 → 拒绝（语义冲突）；同词不同类别 / 场景 / 锚点 → 拒绝，先 `remove` 再学；
- 口水词：不许等于、包含或被包含于任何信息词（症状词、触发词、排除词、锚点标记、建造/修复/诊断动词、坏味道、尝试语、`content_nouns`，以及学习层的触发词、锚点标记和诊断动词，不论候选还是生效）；单字只允许语气词类；
- 诊断动词：不许单字；已在种子层 → 跳过；不许是修复动词、`generic_words`、种子触发词、锚点标记、口水词；
- 触发词：不许单字，不许是 `generic_words`（报 / 错误 / 异常 / 问题 / 不行 / 失效 / 超时 / 满…）或排除词，已含同场景种子词的视为重复、跳过；
- 每桶上限 200 条：满了先淘汰 count 最低且最旧的**候选**（count<2）；全是生效词条时拒绝新增，提示先 `prune`；
- 读写都经脚本：写操作持排他锁完成读-改-写，读操作持共享锁（锁文件 `lexicon.json.lock` 建不了时无锁只读）；原子写入并保留原文件权限；
- 学习层条目缺字段时，读命令跳过并告警，写命令原样保留，不崩溃；
- 测试一律用环境变量 `BAIHUA_LEXICON` 指向临时词库副本，不碰真实词库。
